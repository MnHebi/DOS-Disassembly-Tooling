Create an **independent** `DOS Disassembly Tooling` repository from the supplied DDT source starter. Do not add this code inside CEO. Read `AGENTS.md` and `docs/BLUEPRINT.md` first. Linux x86-64 and Windows x86-64 are equally important targets; both must be built and smoke-tested on their own OS runners before reporting success.

Inspect the actual CEO checkout, **read-only**. Begin by running `python migration/audit_ceo.py <CEO_CHECKOUT>` to enumerate the candidate source files, then inspect the latest checkout and validate paths/imports. Look also for Ghidra export, DOSBox-X launch/capture and independently reconstructed address/SSA utilities not in the candidate list. Return a concise table giving origin file/function/hash, portability verdict (`verbatim`, `extract`, `adapt`, `reference-only`, `reject`), coupling, required tests and target DDT module. Never silently treat generated analysis outputs as reusable code.

Choose **one** low-coupling, demonstrably reusable algorithm, preferentially the byte-run/snapshot comparator or original-file/loaded-image coordinate conversion. Port narrowly into DDT, remove CEO semantics, and add synthetic generic fixtures plus an independent local equivalence check where possible. Record provenance in `docs/PROVENANCE.md`. No original CEO executables, save files, runtime fixtures, disassemblies, scenario data or milestone hashes should be shipped in DDT. Preserve all original input bytes, edits and accepted work untouched.

Maintain a small dependency-free Python core and optional providers. No REA dependency, no MCP server, no replacement game engine, no GUI automation, no persistence service. Prefer saved Ghidra project export (read-only) over throwing away analyst annotations via a new temporary project. Keep segmented coordinates, source offsets, relocation sites, overlays, and unknown runtime effects distinct; do not claim unknown indirect readers/writers are absent. Use concise structured output and existing single-purpose scripts to reduce agent tool/polling costs.

Only after the selective port, run focused tests, then platform CI tests and native packaging/smoke on both OS. Report independently observed results, tool calls, test results and limitations. Do not claim Windows is supported based on Linux-only execution. Stop with a bounded port and audit report; do not start broad dataflow/emulation additions without an observed need. Avoid reopening historical CEO phases.
